Project 03 / Artificial Intelligence

When every turn matters, finding a route becomes more than a navigation problem.

Imagine an emergency situation where someone needs to reach a hospital.

There may be several possible routes, different locations, and multiple paths connecting them. How can an algorithm help identify a suitable route? This project explores that question through graph-based search.

02 / The Context

Why it exists

As part of an AI project, our team explored the idea of an intelligent emergency hospital routing system.

The goal was to model locations and connections as a graph and investigate how search algorithms could help find routes to emergency facilities.

03 / The Challenge

What needed solving

The interesting part wasn't simply finding a path between two points.

It was understanding how to represent a real-world navigation problem computationally and how an algorithm could explore possible routes.

04 / The Journey

How it came together

I contributed to the algorithmic side of the team project (a two-person team).

We explored graph representation and search strategies, including A* search, alongside map-based routing concepts using OpenStreetMap.

The work involved thinking about locations as nodes, connections as edges, and how search algorithms can navigate through a network.

Coming soon: graph representation, implementation screenshots and algorithm workflow.

05 / The Reveal

Turning a navigation problem into a search problem.

The project brings together graph theory, artificial intelligence concepts, and practical route-planning ideas.

Coming soon: system diagram, map visualization and implementation screenshots.

06 / The Reflection

What I took from it

This project helped me connect theoretical AI concepts with a practical problem.

It strengthened my understanding of graph-based problem modelling and search algorithms, while showing me how much planning is involved before an algorithm can solve a real-world task.

Future exploration: improving the routing system, testing different search strategies, and evaluating its behavior across more scenarios.

07 / The ending

Every project leaves something behind.

Before an algorithm can solve a real-world problem, the problem has to be modelled well.

Sometimes it's a working application. Sometimes it's a new skill, a better question, or a completely different way of looking at a problem. These projects are part of my ongoing journey through Data Science and technology.

More experiments, more questions, more things to build.
